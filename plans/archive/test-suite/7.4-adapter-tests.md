# 7.4 — Adapter tests with recorded fixtures

> **Goal:** record one real Gmail API response per operation, replay it forever against `GmailTransport` + `GmailInboxSource`. No live Gmail from CI.
>
> **Depends on:** [7.1](./7.1-repository-fakes.md) (for `FakeMailTransport`-style helpers if needed). **Feeds:** 7.7 (integration).

## What to write

Record one real Gmail API response per operation (send, get, insert, delete, history.list, messages.get) into a JSON fixture. The test replays the fixture against the adapter.

```ts
// adapters/gmail-transport.test.ts
import { GmailTransport } from "@/adapters/gmail-transport";
import { fakeGmailClient } from "../helpers/fakes/gmail-client";
import sendResponse from "./gmail-transport.fixture.json";

describe("GmailTransport", () => {
  it("send returns the assigned id and threadId", async () => {
    const gmail = fakeGmailClient({ send: sendResponse });
    const transport = new GmailTransport(() => gmail);
    const result = await transport.send({ userId: "me", raw: "abc", threadId: "t1" });
    expect(result).toEqual({ id: sendResponse.id, threadId: sendResponse.threadId });
  });
});
```

### Recording the fixtures (one-time, manual)

Write a one-time script `scripts/record-gmail-fixtures.ts` that hits the real Gmail API with the dev test account and dumps the JSON. Run it **once** locally; commit the JSON. **Never** hit real Gmail from CI.

Operations to record:
- `users.messages.send` → `gmail-transport.fixture.json`
- `users.messages.get` → `gmail-transport.fixture.json`
- `users.messages.insert` → `gmail-transport.fixture.json`
- `users.messages.delete` → `gmail-transport.fixture.json`
- `users.history.list` → `gmail-inbox-source.fixture.json`
- `users.messages.get` (inbox variant) → `gmail-inbox-source.fixture.json`

### `GmailInboxSource` (`adapters/gmail-inbox-source.ts`)

Same pattern — replay `history.list` + `messages.get` fixtures. Covers the OAuth client fetch + the response-shape decoding.

### What these tests catch

That the adapter correctly maps Gmail's raw JSON into the `MailTransport` / `InboxSource` domain shapes — the only place a Gmail-API field-name or shape change would surface. They do NOT test the OAuth flow itself (that's `integration/token-refresh.test.ts` in 7.7).
