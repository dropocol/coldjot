# Step 5 — `upgrade/next-16` (apps/web only) — HIGHEST RISK, LAST APP MAJOR

> Branch: `upgrade/next-16` off the merged `upgrade/express-5`.
> Bump next 15.1 → **16.2.10** (latest). This is the highest-risk step → move slowly, one breakage at a time.

## Goal
Bring the web app to Next 16. By this point we're already on Node 24, React 19.2, ESLint 10 flat config, and Tailwind 4 — so the Next-specific breakage is the only thing left.

## Bumps
- `apps/web/package.json`:
  - `next` `^15.1.6` → `^16.2.10`
  - `eslint-config-next` `^15.1.6` → `^16.2.10` (match Next major)
  - Pin `react` / `react-dom` to whatever Next 16 requires (likely still 19.x — verify at exec; we're already on 19.2.7 from Step 0).
  - Audit `@next/*` deps if any (none seen in web package.json).

## Breaking changes to handle
> Verify each against the official Next 16 upgrade guide at exec time (URL: nextjs.org/docs/app/building-your-application/upgrading).

### 1. `next lint` removed (was deprecated in 15.5) 🔴
- `apps/web/package.json` `"lint": "next lint"` → `"lint": "eslint ."`.
- We already set up `apps/web/eslint.config.js` (flat config) in **Step 2**, so this is a one-line script change. Verify `eslint .` picks up the flat config and passes.

### 2. App Router / config defaults
- Audit `apps/web/next.config.*` for deprecated flags (e.g. removed `swcMinify`, changed `experimental.*`, Image defaults, `esmExternals`).
- Next 16 may change **default** behaviors (caching, ISR, fetch caching semantics). Read the diff of `next.config.*` against the upgrade guide and pin any flag whose default flipped.

### 3. Async request APIs (carried from 15.x)
- Next 15 made `cookies()`, `headers()`, `draftMode()`, `params`, `searchParams` **async** (return Promises). Verify all call sites in `apps/web/src` already `await` them. If the codebase was written for Next 14 patterns, these need `await` added. (Likely already done since we're on 15.1, but double-check — this is a common 15→16 runtime crash.)

### 4. Turbopack / build defaults
- Next 16 may flip Turbopack to the default bundler for `next build`. The dev script already uses `--turbopack`. Verify `next build` still produces the expected `.next/` output and the prod start works.
- If Turback build is unstable, fall back to webpack via config (if still supported) — but prefer keeping the v16 default.

### 5. Middleware / Edge runtime
- Audit `apps/web/src/middleware.ts` (if present) for Edge-runtime API changes. Next 16 tightened the Edge runtime's Node-API surface.

### 6. Minimum version bumps (already satisfied)
- Node ≥ 24 ✅ (Step 0), React 19 ✅ (Step 0). Confirm Next 16 doesn't require React 20 (unlikely as of 2026).

## Risks & rollback
- **Build/runtime regressions** are the main risk. Next 16 is a real major.
- **Async request APIs** are the most common silent breakage — a missing `await` compiles but crashes at runtime.
- **`next lint` removal** is mechanical (Step 2 paved the way).
- Rollback: revert the commit; `npm install` restores Next 15. Because each step is its own branch, this revert is clean.
- **If Next 16 proves too unstable**, this step can be deferred (stay on latest 15.5.x) without blocking Steps 0–4 and 6–7. The other majors are independent.
