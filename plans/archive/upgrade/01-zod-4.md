# Step 1 — `upgrade/zod-4` (both apps)

> Branch: `upgrade/zod-4` off the merged `chore/align-foundation`.
> Bump `zod` 3.24 → 4.4.3 (latest). Also bump `@hookform/resolvers` to a zod-4-compatible release.

## Goal
Move zod to v4 across `apps/web` and `apps/mailops`. The breaking surfaces were mapped during planning and are **small and bounded** (12 zod-importing files total).

## Bumps
- `apps/web/package.json`: `zod` `^3.24.1` → `^4.4.3`; `@hookform/resolvers` `^3.10.0` → `^5` (latest, zod-4-compatible — confirmed via web search Sept 2025). Verify exact version at exec.
- `apps/mailops/package.json`: `zod` `^3.24.1` → `^4.4.3`

## Breaking surfaces + fixes

| File | Issue | Fix |
|---|---|---|
| `apps/web/src/lib/http/validation.ts` | `ZodType<Output, z.ZodTypeDef, unknown>` (3 type params) + `z.ZodTypeDef` | Migrate to zod-4 2-param `ZodType<Output, Input>`; drop `z.ZodTypeDef`. This is the **central helper** used by `parseBody`/`parseQuery`, so fixing it unblocks the route files. |
| `apps/mailops/src/routes/pubsub.ts` | `z.record(z.string())` — single-arg form **removed** in v4 | → `z.record(z.string(), z.string())` (key + value schema required) |
| `apps/web/src/lib/schemas/index.ts`<br>`apps/mailops/src/routes/mailbox.ts`<br>`apps/mailops/src/types/watch.ts` | `z.string().email()` — **deprecated** in v4 | → `z.email()` |
| `apps/web/src/lib/http/validation.ts` (`.flatten()`, 2 sites)<br>`apps/web/src/app/api/sequences/[id]/contacts/{list,bulk}/route.ts` (`.format()`, 2 sites)<br>`apps/mailops/src/routes/mailbox.ts` (`.issues` + `issue.path.join(".")`, 1 site) | Hand-rolled error formatting — v4 changed `ZodIssue.path`/`code` types | Audit each formatter against zod-4's `ZodError` shape; adjust so the **API response shapes stay identical** (these feed client-facing 400 bodies). |
| `apps/web/src/components/settings/profile-form.tsx` | `zodResolver` from `@hookform/resolvers/zod` | Bump `@hookform/resolvers` (done in Bumps). Import `{ z } from "zod"` still valid in v4. |

### Coercion (likely no change)
`z.coerce.number()` appears in both `env.ts` files + `apps/web/src/lib/schemas/index.ts`. Retained in v4 — verify message handling only if a test fails.

### Not present in this repo (no action needed)
`z.setErrorHandler`, `z.config`, custom `errorMap`, `z.discriminatedUnion`, `z.intersection`, `z.union`, `z.preprocess`, `z.transform`, `z.any/unknown/never/void/nan`, `z.map/set/promise`, `.catch/.brand/.refine/.superRefine`, `z.lazy`, `z.instanceof`, `z.custom`. (Confirmed via grep across all 12 files.)

## Verification
1. `npm install` succeeds.
2. `tsc --noEmit` passes in both apps.
3. `npm run build` succeeds.
4. `npm run lint` passes.
5. **Runtime:**
   - Boot both apps with a **missing required env var** → must crash at startup with a clear zod error (not a silent later failure). This is the whole point of the env schemas.
   - Boot with all envs present → normal startup.
   - POST an invalid body to an API route (e.g. `/api/sequences/:id/contacts/bulk` with a non-array) → must return **400** with the **same error shape** as before (snapshot the shape pre-upgrade to compare).
   - Submit the profile form (`/settings`) with invalid data → must show validation errors via `zodResolver`.

## Risks & rollback
- **Error-shape drift** is the main risk — clients may depend on the exact `.format()`/`.flatten()` output. Snapshot before, compare after.
- **`@hookform/resolvers` version mismatch** is the #1 reported zod-4 issue (per Stack Overflow / Reddit). Ensure both `zod` and `@hookform/resolvers` move together.
- Rollback: revert the commit; `npm install` to restore zod 3.
